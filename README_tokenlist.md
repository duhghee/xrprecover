# XRPRecover Tokenlist Creator
===========================

File: tokenlist.py

# OVERVIEW
--------
- tokenlist.py is a desktop graphical tool for building a tokenlist.txt file from known words and possible word candidates. 
- It offers 12 configurable rows, including fixed-position candidates and unanchored candidate sets.

* The program only writes a text file. It does not recover wallets, test phrases, connect to a wallet, or run XRPRecover.

# REQUIREMENTS
------------
- Python 3 with Tkinter support.
- No third-party Python packages are required.
- A text wordlist is optional for manually entered words. For wordlist-based sources, provide a UTF-8-compatible text file with one word per line.

* On some Linux distributions, Tkinter must be installed separately (for example, with the distribution's python3-tk package).

# STARTING THE PROGRAM
--------------------
1. Save tokenlist.py to a folder on your computer.
2. Open a terminal or command prompt in that folder.
3. Run:

        python tokenlist.py

   On systems where Python 3 is named python3, run:

        python3 tokenlist.py

4. The tokenlist creator GUI window opens.

# WORDLIST SETUP
--------------
The Wordlist field initially contains "english.txt". This is a relative path,
so it refers to the current working directory unless you select another file.

- Click "Browse..." to choose an existing wordlist file.
- Click "Reload" to refresh candidate counts after changing the file.
- Wordlist files should contain one word on each nonempty line.
- Blank lines are ignored; leading and trailing whitespace is removed.

* A missing wordlist is treated as an empty list: manual entries can still be used, but wordlist-based sources will contain zero candidates.

# CONFIGURING THE 12 ROWS
-----------------------
* Each row has the following fields:

- Pos.................................Row number, 1 through 12.
- Behavior................................"Fixed" or "Permute".
- Source.................Method used to choose candidate words.
- Value..................Word or custom words, when applicable.
- Length...Selected length for "Words by length" (3 through 8).
- Candidates.............Number of words selected for that row.

* Behavior:
- Fixed: each candidate is prefixed with its numbered position, for example ^1^abandon. 
  All fixed candidates from one row appear on one output line.
- Permute: candidates are written without position prefixes, on one output line. 
  The GUI describes these as unanchored candidate-set lines, which the intended XRPRecover workflow assigns among positions without fixed candidates.

* Sources:
- Single word: enter one candidate in the Value field.
- Custom words: enter candidates separated by whitespace in Value.
- Words by length: use every word in the selected wordlist that has the chosen number of characters. Use the Length drop-down (3-8).
- All wordlist words: use every nonempty word from the selected wordlist.

* For wordlist-based sources, the Value field is ignored. For other sources, the Length selector is disabled.
* Rows with no candidates are omitted from the generated file. 
* The program updates candidate counts and a bottom status summary automatically.

# EXAMPLE
-------
* Suppose you configure:

Row 1: Fixed   / Single word  / abandon
Row 2: Fixed   / Custom words / ability able
Row 3: Permute / Custom words / about above absent

* The output text is:

^1^abandon
^2^ability ^2^able
about above absent

* A "Permute" row is not anchored to the displayed row number; a "Fixed" row is.
  This example illustrates the file generated by this GUI, not a guarantee that any particular recovery tool will accept the tokenlist or find a phrase.

# BUTTONS
-------
- Clear All.............Resets all rows to blank "Fixed / Single word" entries; the chosen wordlist path is retained.
- Load Template.........Loads saved row settings and wordlist path from JSON.
- Save Template.........Saves the current settings and wordlist path to JSON.
- Preview...............Displays the output tokenlist text without saving it.
- Generate..............Opens a Save dialog and writes the generated UTF-8 text.

* The saved JSON template stores configuration, not a copy of the wordlist.
* If you move the template to another computer, check its wordlist path.

# OUTPUT NOTES
------------
- Each configured row produces one line, in ascending row order.
- Fixed candidates are written as ^POSITION^word.
- Permute candidates are written as space-separated words, without anchors.
- There is no built-in duplicate removal, token validation, or estimate of the total search space. 
- The candidate counts are simple counts per row.
- If every row is empty, Generate shows a warning rather than creating a file.
- The output is saved to the location you choose, typically tokenlist.txt.

# IMPORTANT LIMITATIONS
---------------------
- The program does not check whether a phrase is valid or compatible with a particular wallet or recovery tool.
- It does not verify the syntax or behavior of external BTCRecover/XRPRecover versions. 
- Consult the documentation for the recovery tool you plan to use.
- Large wordlists can create very long lines and large output files.
- Only enter recovery-related information on a computer you trust. 
- Treat the generated tokenlist and saved templates as potentially sensitive files.

# TROUBLESHOOTING
---------------
1. Window does not open:
  Confirm Python 3 and Tkinter are installed, and run the script from a
  graphical desktop session.

2. Wordlist candidate counts show 0:
  Confirm the Wordlist path points to a readable text file, then click Reload.
  For "Words by length", confirm there are words of the selected length.

3. Generate says no configured tokens:
  Enter at least one word or choose a wordlist-based source with candidates.

4. Wrong position in output:
  Use "Fixed" for anchored positions. "Permute" deliberately omits the
  position number, even though its configuration appears on a numbered row.

5. File not saved where expected:
  Check the destination selected in the "Generate tokenlist.txt" Save dialog.

# GITHUB / MODES 9 AND 12
------------------------
- Mode 9 tests tokenlist candidates against a target XRP classic address.
- Mode 12 writes BIP-39 checksum-valid tokenlist combinations without
  checking a target XRP address; output is under mode12_results/.
- Never commit tokenlist.txt, recovered phrases or generated output files.
- On Windows, install the Python packages with
  `py -m pip install -r requirements.txt` before running xrprecover.py.
- On Ubuntu 24.04, the GUI requires `sudo apt install python3-tk`.
