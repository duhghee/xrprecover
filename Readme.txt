XRP-RECOVER - README
====================
File: xrprecover.py
Purpose: Recover, test, generate, and validate 12-word English BIP-39
         mnemonic phrases for XRP classic (r...) addresses.

OVERVIEW
--------
xrprecover.py is an interactive, command-line tool with 15 modes. It
validates BIP-39 checksums, derives XRP classic addresses, and can search
candidate phrases using known words, missing positions, incorrect words,
word-order permutations, or a tokenlist generated by tokenlist.py.

IMPORTANT SCOPE
---------------
- Supports exactly 12-word English BIP-39 mnemonic phrases.
- Uses the secp256k1 XRP classic address derivation path
  m/44'/144'/0'/0/0 for single-address operations. Mode 5 displays the
  first 10 addresses at m/44'/144'/0'/0/0 through m/44'/144'/0'/0/9.
- Uses an EMPTY BIP-39 passphrase. Wallets made with a nonempty BIP-39
  passphrase or a different derivation path may yield another address.
- A BIP-39 mnemonic is NOT the same thing as an XRPL family seed starting
  with "s". This tool does not recover XRPL family seeds.
- Uses a target XRP classic address when a mode requests one. An XRP
  classic address starts with "r" and is case-sensitive.
- Does not connect to the XRP Ledger, inspect balances, or move funds.
- Intended only for wallets you own or are authorized to recover.

REQUIREMENTS
------------
- Python 3.8 or later (Python 3.10+ recommended)
- Python packages: mnemonic, bip-utils, coincurve
- A terminal or command prompt
- Adequate CPU, time, and disk space for the search you choose

INSTALLATION
------------
1. Put xrprecover.py in a folder of your choice.
2. Open a terminal in that folder.
3. Create a virtual environment and install requirements.txt.

   Windows (Command Prompt):
       py -m venv .venv
       .venv\Scripts\activate.bat
       python -m pip install --upgrade pip
       python -m pip install -r requirements.txt

   Windows (PowerShell):
       py -m venv .venv
       .\.venv\Scripts\Activate.ps1
       python -m pip install -r requirements.txt

   Ubuntu 24.04 / Linux:
       sudo apt update
       sudo apt install -y python3-venv python3-tk build-essential
       python3 -m venv .venv
       source .venv/bin/activate
       python -m pip install -r requirements.txt

   If PowerShell blocks script execution, use Command Prompt, rather
   than changing system-wide script execution policy. The main CLI
   program does not require Tk; python3-tk supports tokenlist.py.

4. Start the program while the environment is active:

   python xrprecover.py

   The program displays a numbered menu. Enter one mode number (1-15)
   and follow the prompts. Each invocation runs one selected operation.

COMMAND-LINE OPTIONS
--------------------
Usage:

   python xrprecover.py [--mode 1-15] [--mnemonic WORDS] [--address r...]
                        [--processes N] [--batch-size N]
                        [--pbkdf2-backend {auto,reference}]

Examples:

   python xrprecover.py --processes 4
   python xrprecover.py --processes 8 --batch-size 2048
   python xrprecover.py --pbkdf2-backend reference
   python xrprecover.py --mode 14 --mnemonic "word1 ... word12" --address rYOURADDRESS
   python xrprecover.py --mode 15 --mnemonic "word1 ... word12" --address rYOURADDRESS
   python xrprecover.py --help

--processes N
   Number of parallel CPU workers (default: detected CPU count).
   Applies to multiprocessing search modes, including 1-3, 6, and 8-15.

--batch-size N
   Candidate phrases submitted per worker task (default: 1024).

--pbkdf2-backend auto|reference
   auto: use an optional, locally verified AVX2/PBKDF2 accelerator only
         if supporting files and approved benchmark configuration exist.
   reference: always use the standard Python/library derivation backend.
   The native accelerator is OPTIONAL; it is not required to use the tool.
   The code looks for pbkdf2_backend.json, libpbkdf2_avx2.so, and the
   pbkdf2_native module beside xrprecover.py when auto acceleration is
   configured. Do not download or execute untrusted native libraries.

MODES 1-15
----------
[1] Scan positions for ONE wrong word
    Enter 12 words and a target XRP classic address. Try replacing one
    word at a time with English BIP-39 words; leave the other 11 positions
    unchanged. Matching phrases are saved to position_matches.txt.

[2] Find trailing words matching an ADDRESS PATTERN
    Enter known beginning words and a case-sensitive XRP address suffix
    (or the full classic address). Fill remaining trailing positions and
    report valid phrases whose derived addresses end with that pattern.
    Results are saved to pattern_matches.txt. A short suffix can produce
    unrelated matches; it is not equivalent to a full address check.

[3] Print valid seeds with MISSING TRAILING words
    Enter the known beginning words and the number of missing words, so
    the total is exactly 12. Generate BIP-39 checksum-valid completions.
    This mode does NOT compare against a target XRP address, and it only
    outputs phrases whose 12 words are all distinct. Results are streamed
    to mode3_results/<timestamp>/missing_words_0001.txt, etc., with at
    most 10,000,000 phrases in each file. It may consume substantial disk.

[4] Validate ONE seed phrase
    Enter exactly 12 words. Report whether the mnemonic passes BIP-39
    validation and, if valid, display its derived XRP classic address.

[5] Display the FIRST 10 XRP addresses for a seed phrase
    Enter a valid 12-word English BIP-39 mnemonic. Mode 5 derives and
    prints 10 XRP classic (r...) addresses, each labeled with its full
    derivation path, in ascending address-index order:

       m/44'/144'/0'/0/0: r...
       m/44'/144'/0'/0/1: r...
       m/44'/144'/0'/0/2: r...
       ...
       m/44'/144'/0'/0/9: r...

    The first four path components stay the same; the final index varies
    from 0 through 9. Mode 5 uses an empty BIP-39 passphrase and does
    not require a target address. Results are printed to the terminal
    only; it does not create an output file or check balances. Other
    modes continue to use address index /0.

[6] Descramble a 12-word phrase
    Enter 12 scrambled BIP-39 words. Check all 12! possible word orders
    for valid BIP-39 checksums, without looking up a target address.
    The mode rejects repeated input words and outputs only phrases with
    distinct words. Valid results go to descrambled.txt.
    CAUTION: 12! = 479,001,600 permutations; processing may be lengthy.

[7] Generate a new seed phrase and XRP classic address
    Generate a fresh 12-word BIP-39 mnemonic and display its first XRP
    classic address. Saves the PRIVATE seed phrase and public address in
    plaintext in new_seed.txt. Protect this file and never share the seed.

[8] Recover 1-4 missing words at KNOWN positions
    Enter exactly 12 space-separated positions and replace each missing
    word with a literal ? character. Supply the target XRP classic
    address. Known words stay in their original positions while each
    missing position is filled from the English BIP-39 word list.
    Stops at the first address match. Saves any result to
    missing_positions_matches.txt.

    Format example (illustrative only, not a real recovery target):
       abandon ? ability about ? above absent absorb abstract absurd abuse access

[9] Search tokenlist.txt generated by tokenlist.py
    Enter the path to a tokenlist file (press Enter for tokenlist.txt),
    then the target XRP classic address. The file must define exactly
    12 nonempty candidate rows. Fixed rows anchor choices to specified
    positions; floating rows can exchange ONLY among unfilled positions.
    Stops at the first address match. Saves matching phrases to
    tokenlist_matches.txt. See TOKENLIST FORMAT below.

[10] Scan for exactly TWO wrong words
     Enter 12 words and a target XRP classic address. Replace exactly
     two positions while keeping the other ten words in order. Stops at
     the first address match. Saves to two_wrong_word_matches.txt.

[11] Scan for exactly THREE wrong words
     Enter 12 words and a target XRP classic address. Replace exactly
     three positions while keeping the other nine words in order. Stops
     at the first address match. Saves to three_wrong_word_matches.txt.
     This search can be impractically large with all 2,048 BIP-39 words.

[12] Generate checksum-valid phrases from a tokenlist
     Read a 12-row tokenlist like Mode 9, but output BIP-39 valid seed
     phrases WITHOUT checking a target XRP address. Files are stored
     under mode12_results/<timestamp>/; can consume considerable disk.

[13] Match an XRP address from missing TRAILING words
     Keep known leading words fixed and enumerate the requested number
     of missing trailing words. Stops on an address match and writes
     mode13_results/<timestamp>/target_match.txt. --allow-print opts in
     to displaying the recovered phrase in the terminal.

[14] ONE wrong word + permute ALL 12 positions
     Provide exactly 12 DISTINCT valid English BIP-39 input words and a
     target XRP classic address. Replace one input word with a new word
     from the configured wordlist, then permute all 12 positions.
     Stops at the first address match. Output: mode14_matches.txt.
     Extremely large search space; not practical to exhaust ordinarily.

[15] TWO wrong words + permute ALL 12 positions
     Provide exactly 12 DISTINCT valid English BIP-39 input words and a
     target XRP classic address. Remove exactly two input words, insert
     two distinct words not already in the input, and permute all 12
     positions. Stops at the first match. Output: mode15_matches.txt.
     Full exhaustive search is generally computationally infeasible.

TOKENLIST FORMAT (MODE 9)
-------------------------
Use tokenlist.py to create the file or write it as UTF-8 plain text.

- Each populated line holds one OR MORE alternative BIP-39 words.
- Anchored alternatives look like ^POSITION^word (positions 1-12).
- All anchored alternatives on a line must have the SAME position.
- Floating (unanchored) lines list plain words separated by spaces.
- Do NOT mix anchored and unanchored words on a single line.
- Each fixed position may appear on only one line.
- There must be EXACTLY 12 populated rows in total, fixed + floating.
- Blank lines and lines starting with # are ignored; a blank line is not
  a wildcard and does not automatically include the full dictionary.
- Every listed word must be present in the English BIP-39 word list.
- Repeated alternatives within one row are checked only once.
- Floating rows can be assigned in different orders to the positions
  NOT already occupied by fixed rows; identical floating rows do not
  generate redundant row permutations.

Example tokenlist.txt (illustrative; no known matching address):

   # Ten fixed-position rows
   ^1^abandon ^1^ability
   ^2^about
   ^3^above
   ^4^absent
   ^5^absorb
   ^6^abstract
   ^7^absurd
   ^8^abuse
   ^9^access
   ^10^accident
   # Two floating rows: assigned to positions 11 and 12
   achieve acid
   acoustic acquire

There are 12 populated rows here: 10 fixed and 2 floating. The last
2 candidate sets may trade positions 11 and 12; positions 1-10 remain
fixed. The full search tests checksum-valid phrases against the address
provided when Mode 9 is selected.

WORKFLOW WITH TOKENLIST.PY
--------------------------
1. Launch tokenlist.py (separate GUI tool).
2. Configure 12 populated rows with Fixed or Permute behavior.
3. Choose candidate word sources and generate tokenlist.txt.
4. Run xrprecover.py and select Mode 9.
5. Enter the generated tokenlist.txt path and your XRP classic address.

SEARCH PROGRESS AND PERFORMANCE
-------------------------------
Search modes display total candidates, checked candidates, remaining
candidates, rate per second, ETA, and a progress bar. The candidate
count includes phrases rejected by the BIP-39 checksum.

- The program streams candidate batches instead of building every
  candidate phrase in memory.
- Several modes stop immediately after finding the first address match:
  8, 9, 10, 11, 13, 14, and 15. Other modes may continue searching.
- Search spaces grow exponentially or factorially. Even one additional
  unknown word can drastically increase time requirements.
- Press Ctrl+C to interrupt. Progress is printed, but the program does
  not implement a persistent checkpoint/resume mechanism.
- Match files are created only when a result is found for the relevant
  mode (except Mode 7, which writes a freshly generated seed file).

OUTPUT FILES
------------
Mode 1:  position_matches.txt
Mode 2:  pattern_matches.txt
Mode 3:  mode3_results/<timestamp>/missing_words_0001.txt, ...
Mode 4:  terminal only
Mode 5:  terminal only
Mode 6:  descrambled.txt
Mode 7:  new_seed.txt
Mode 8:  missing_positions_matches.txt
Mode 9:  tokenlist_matches.txt
Mode 10: two_wrong_word_matches.txt
Mode 11: three_wrong_word_matches.txt
Mode 12: mode12_results/<timestamp>/tokenlist_valid_seeds_0001.txt, ...
Mode 13: mode13_results/<timestamp>/target_match.txt
Mode 14: mode14_matches.txt
Mode 15: mode15_matches.txt

Output paths are relative to the current working directory, not
necessarily to the folder holding xrprecover.py. Most result files are
written again on subsequent successful runs; Mode 3 uses a new dated
folder and does not silently overwrite its existing numbered files.

TROUBLESHOOTING
---------------
"ModuleNotFoundError" (mnemonic, bip_utils, or coincurve):
   Install packages with the SAME Python interpreter that runs the tool:
      python -m pip install -r requirements.txt

"Invalid XRP classic address":
   Use a complete case-sensitive XRP classic r-address. An X-address,
   wallet seed starting with s, or incomplete address is not accepted.

"Unknown BIP-39 word" or "Invalid seed phrase":
   Check spelling, use English BIP-39 words, and verify that there are
   exactly 12 words. Passing the checksum does not prove wallet ownership.

"Tokenlist ... exactly 12 populated rows are required":
   In Mode 9, provide exactly 12 nonempty candidate lines. A blank GUI
   row does not represent a missing word; populate it explicitly.

Very slow scan or very large estimated candidate count:
   Reduce uncertainty or use narrower candidates. Try fewer CPU workers
   if the system becomes unresponsive. Modes 6, 14, 15 and three/four missing-word
   searches can be particularly demanding.

"Native PBKDF2 unavailable":
   The optional accelerator was not usable; the tool reports fallback
   to its reference backend. Run with --pbkdf2-backend reference if you
   prefer to explicitly disable native acceleration.

SECURITY AND PRIVACY
--------------------
Recovery phrases grant control over wallet assets. Run the tool in a
trusted environment, preferably offline, and never paste a live phrase
into an untrusted website or share screenshots containing seed words.
Output files (especially new_seed.txt and recovery matches) may contain
complete PRIVATE mnemonics in plaintext. Treat them as highly sensitive;
store them encrypted or securely remove them when no longer needed.
Avoid cloud-synced folders, shared computers, shell/session logging, and
unnecessary backups when handling real recovery phrases. Make sure the
XRP address is yours before running an address-match search.

LIMITATIONS
-----------
- No ledger or balance checks; no transaction signing or fund transfer.
- English, 12-word BIP-39 only; no 15/18/21/24-word phrases.
- Empty BIP-39 passphrase throughout. Modes other than Mode 5 derive
  only the /0 address at m/44'/144'/0'/0/0; Mode 5 lists indices /0-/9
  on the same account/change path. Other paths are not scanned.
- No automatic resume after cancellation.
- Results depend on the user's word candidates and target address.
- Passing BIP-39 validation is not evidence that the address contains XRP.

This README describes the uploaded xrprecover.py implementation; it is
not a guarantee that a search will find a missing mnemonic or recover funds.
